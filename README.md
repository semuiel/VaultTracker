# VaultTracker 0.16.3-preview

Актуальная сборка для Folia 26 и Java 25: [`outputs/VaultTracker-0.16.3-preview-folia26.jar`](outputs/VaultTracker-0.16.3-preview-folia26.jar). Исходный код находится в `src/main`, тесты — в `src/test`, встроенный сервис пожертвований — в `donations`. Собрать и проверить проект: `gradlew.bat test shadowJar` (Windows, Java 25) или `./gradlew test shadowJar` (Linux, Java 25). Готовый JAR появится в `build/libs`.

Плагин ведёт каталог ресурсов в сундуках с табличкой `[v]` или `[vault]`, обслуживает торгового Telegram-бота FLEXITY, уведомления об изменениях сундуков, личный кабинет и функции администраторов. В поиске собственных ресурсов можно выбрать точный сундук для компаса. Бот умеет показывать администратору участника события и предложить личное сообщение, бан на пять минут и заморозку через установленный Flexity. У обычного игрока имя участника в уведомлении скрыто. Дополнительные настройки прав администратора находятся в меню суперадминистратора.

После успешной привязки Telegram-аккаунта плагин выполняет от консоли `/bastion trust add <ник>` для игрока онлайн. Если Bastion недоступен или игрок успел выйти, выдача остаётся ожидающей и повторяется при следующем входе. У супер администратора в карточке игрока есть добавление и удаление доверия Bastion; обычным администраторам это право включается отдельно в меню возможностей. Команды Bastion требуют, чтобы игрок был в сети. Установленный Bastion подключается как необязательная зависимость и проверяется перед выполнением.

Примеры конфигурации лежат в `src/main/resources`; реальные токены Telegram, ключи пожертвований, пароли и файлы баз данных должны оставаться на сервере. Установка JAR и перезагрузка плагина выполняются администратором сервера. История предыдущих версий и подробности настройки приведены ниже.

## Предыдущая версия 0.12.1 — Folia 26.1.2 / 26.2

Сборка с минимальным API Folia `26.1.2.build.8-stable`, требуется Java 25. Исправлено отклонение плагина с ошибкой `Unsupported API version 26.2` на сервере 26.1.2. Используется общий API Adventure 4/5; тесты также запускаются с API 26.2 (`-PtestFoliaApi=26.2.build.7-beta`). Поддерживается поиск сохранений офлайн-игроков в `players/data` при новой структуре `dimensions/<namespace>/<dimension>`. Для сервера 1.21.11 используйте прежний JAR 0.11.2. Конфиги и базы плагина сохраняются.

Пинг в `/list` выравнивается справа в отдельную колонку с моноширинными никами; значки измерений сохраняются. Работает автоматически при `list.showPing: true` со стандартной строкой `{emoji} {name}` или `{emoji} {name}{ping}` и `listPing` без HTML. `list.alignPing: false` возвращает компактный вид. Ширина вычисляется по всему списку, включая остальные страницы.

Подтверждения и уведомления команд Telegram-репортов и модерации удаляются через 30 секунд. Репорты в админской теме сохраняются; сроки `/list` и торгового бота не меняются.

Добавлены `/topitem all [страница]` с суммарным рейтингом в шалкерах, короткий маркер `[v]`, раздел супер администратора «Дети» и Telegram-репорты ответом на сообщение. Добавление детей — по игровому нику или Telegram ID связанного аккаунта; доступны размеры 0.6/0.75/1, +2 сердца и защита 20%. [Установка и команды 0.11.0](outputs/Changes-0.11.0.md).

Во всех темах групп, указанных в настройках чат-бота, удаляются входящие команды, начинающиеся с `/`, включая `/list`. Удаление выполняется отдельно и не задерживает обработку команд и ответы каталога; ответ со списком игроков удаляется через прежние 300 секунд. Чат-боту нужно право администратора Telegram «Удаление сообщений».

`/list` читает текущее измерение и пинг на потоке каждого онлайн-игрока при запросе и перелистывании. `list.showPing: true` в `telegramchat.yml` добавляет пинг после ника; `false` скрывает его. Удаление списка через `list.messageLifetimeSeconds` (по умолчанию 300 секунд после отправки) работает отдельно от очереди чата, повторяется при сбое Telegram и сохраняет сроки при перезапуске. Подробнее: [изменения 0.10.6](outputs/Changes-0.10.6.md).

Поиск своих ресурсов через `/find` или Telegram временно направляет обычный компас онлайн-игрока к ближайшему найденному сундуку в текущем мире. Через 120 секунд восстанавливается прежняя цель; повторный поиск обновляет цель и срок. Наведение тихое, список результатов сохраняется. Привязки предметов-компасов к магнетиту не изменяются. Если игрок офлайн или результатов в его мире нет, наведение не включается.

Текст сообщений Telegram теперь явно белый. Непривязанные отправители показываются по имени Telegram без добавления @username. `messages.showTelegramTagLinked` и `messages.showTelegramTagUnlinked` независимо включают или скрывают `[TG]` у привязанных и непривязанных пользователей; после изменения выполните `/vtrack reload`. Для шаблона `formats.telegramChat` доступен маркер `{tg}`.

Telegram-сообщения привязанных пользователей отображаются в игре от имени их персонажа с отметкой `[TG]`. Для установленного Flexity используется его форматтер глобального чата, цвет ника и сохранённый пользовательский префикс. Офлайн-настройки читаются из базы Flexity. Без интеграции остаётся игровой ник с `[TG]`; непривязанные пользователи отображаются по Telegram-имени. Переключатель: `messages.linkedPlayerIdentity: true` в `telegramchat.yml` (по умолчанию включён, в том числе для существующих конфигов). Это отображение сообщения: персонаж не выполняет чат-команды, текст не создаёт повторной пересылки в Telegram.

Хранилища регистрируются без лимита. В личном кабинете «Мои ресурсы» доступен поиск по своим сундукам; в игре — `/find diamond_ore` (русские названия и части названий тоже поддерживаются). Результаты содержат предмет, количество, мир и координаты, по 20 строк на странице. Ближайшие сундуки в текущем мире идут первыми, затем другие миры. Если игрок офлайн, Telegram показывает координаты без расчёта расстояния. Поиск использует последние учтённые остатки зарегистрированных хранилищ.

Для Flexity сохраняйте `messages.requirePrefixInMinecraft: "\uE000"`: так пересылается только глобальный чат. `messages.mergeWindowSeconds: 0` отключает накопление, `5` объединяет сообщения за пять секунд. После изменения конфигурации выполните `/vtrack reload`.

Добавлен отдельный мост чата Minecraft ↔ Telegram: [настройка 0.10.1](outputs/TelegramChat-0.10.1.md). Все параметры находятся в автоматически создаваемом `telegramchat.yml`. Поддерживаются отдельный или общий с каталогом токен, общие прокси, независимая тема достижений, `/list` в обеих темах с 20 игроками на странице, кнопками перелистывания и автоудалением через 5 минут, обычные и кастомные Telegram-эмодзи.

## Обновление 0.8.0

- Над списком предметов добавлена кнопка «🏆 Топ по всем предметам». Рейтинг суммирует все ресурсы зарегистрированных хранилищ по UUID игрока (включая офлайн); АР/ИР повторно не прибавляются. Строки компактные: только число шалкеров с округлением до двух знаков, например «Alex — 12,45 шалк.». Единица сравнения — 1728 предметов, независимо от размера стака; это не фактический объём упаковки разных предметов. Для малых ненулевых сумм — «<0,01 шалк.». Доступны перелистывание и возврат к прежнему фильтру списка.

- Все Telegram-списки используют единые категории: 🧱 блоки, 💎 руды/ресурсы, 🛠️ инструменты, ⚔️ оружие, 🛡️ броня, 🍖 еда, 🌱 растения, ⚙️ механизмы, 🧪 зелья/магические предметы, 📚 книги/карты, 🪣 вёдра, 📦 контейнеры. Для остальных предметов — нейтральная точка. Это обозначения категорий, не точные текстуры Minecraft.
- Супер администратор видит инвентарь и эндер-сундук офлайн-игрока, включая броню, вторую руку и вложенные шалкеры. Читается последнее сохранение `playerdata/<UUID>.dat` из загруженных миров; файл не изменяется. Если файлов несколько, выбирается последний изменённый. Поддерживаются строковые ID предметов, современные `components` и старый `tag/BlockEntityTag`. Отсутствие/повреждение файла не обозначается как пустой инвентарь. При входе игрока во время чтения используется онлайн-просмотр. Данные сторонних плагинов раздельных инвентарей не читаются.
- В настройках размера, скорости полёта и передвижения есть «Своё значение»: ввод в личном чате бота от 0.1 до 20, с точкой или запятой, затем подтверждение. `/cancel` отменяет ввод.
- Действия игрока → телепортация к выбранному онлайн-игроку либо на координаты `x y z`, например `223 200 1004`. Координаты относятся к текущему миру перемещаемого игрока. Проверяются высота и граница мира; обе операции требуют подтверждения и онлайн-игрока. Применяется асинхронная телепортация Paper/Folia. Место не проверяется на лаву/свободное пространство: координаты выбирает администратор.
- Уведомления охраны собираются в фиксированные окна по 10 секунд для получателя и владельца. Изъятия и возвраты считаются отдельно; разные места/участники не смешиваются. Подробные события остаются в истории, очередь сохраняется при перезапуске. Очень большой поток делится на дополнительные порции; длинная сводка отсылает к истории. Имя участника доступно только администратору.
- В событиях администратора добавлен поиск по части имени владельца/участника, русскому или английскому названию предмета, месту и номеру события. Фильтр сохраняется при перелистывании.
- VaultTracker больше не пишет собственные служебные записи о действиях супер-администратора в консоль, включая изменения списка Telegram-админов. Сообщение, намеренно отправленное в игровой чат, и собственный вывод других плагинов (например LuckPerms) не подавляются.

При обновлении остановите сервер и замените только JAR. Существующие `config.yml`, `telegram.yml`, `guard.yml`, базы и `telegram.offset` сохраняйте. Новые настройки вручную вводить не требуется. После запуска откройте `/menu` заново.

## Быстрая инструкция владельцу сервера

1. Выдайте игрокам `vaulttracker.register` и `vaulttracker.search` (оба права уже включены по умолчанию).
2. Игрок ставит табличку на хранилище и пишет `[vault]` в первой строке. После регистрации на ней появится его ник.
3. Для проверки выполните `/topitem diamond`, `/topitem Ник` и `/vtrack mine`.
4. После массового изменения хранилищ администратор может выполнить `/vtrack rescan`.
5. После изменения `config.yml` или `telegram.yml` выполните `/vtrack reload`. После замены JAR перезапустите сервер.

Самые полезные запросы:

```text
/topitem diamond       — у кого больше всего алмазов
/topitem Ник           — все ресурсы выбранного игрока
/topitem Ник diamond   — сколько алмазов у выбранного игрока
/itemtop АР            — обычная + глубинная алмазная руда по всем игрокам
/itemtop Ник ИР        — обе изумрудные руды у выбранного игрока
/vtrack mine           — ваши зарегистрированные хранилища
```

## Регистрация хранилища

Поставьте обычную табличку сверху на хранилище или прикрепите её сбоку и напишите `[vault]` на первой строке лицевой стороны. Для подвесной таблички хранилище должно находиться над ней. После регистрации на табличке появятся строки «Собственность», «игрока» и ник владельца.

Одна табличка учитывает обе половины двойного сундука. Сохраняются UUID и имя владельца. Повторная регистрация того же хранилища отклоняется.

## Все игровые команды

Основные команды — `/topitem` и её полный алиас `/itemtop`. Названия предметов можно писать на русском или английском. Для точного английского идентификатора подходит формат Bukkit, например `DIAMOND_ORE` или `minecraft:diamond_ore`.

| Команда | Назначение | Право |
| --- | --- | --- |
| `/topitem предмет` | Топ игроков по выбранному предмету | `vaulttracker.search` |
| `/topitem diamond` | Топ владельцев предмета; опечатки `diamon` и `daimond` распознаются | `vaulttracker.search` |
| `/topitem Alex` | Все ресурсы игрока, по 8 строк на странице | `vaulttracker.search` |
| `/topitem Alex 2` | Вторая страница списка с кнопками «Назад» и «Вперёд» | `vaulttracker.search` |
| `/topitem Alex diamond` | Количество конкретного предмета у игрока | `vaulttracker.search` |
| `/topitem player Stone` | Явно искать игрока `Stone`, если его ник совпадает с названием предмета | `vaulttracker.search` |
| `/itemtop AR` или `/itemtop АР` | Сумма обычной и глубинной алмазной руды по игрокам | `vaulttracker.search` |
| `/itemtop IR` или `/itemtop ИР` | Сумма обычной и глубинной изумрудной руды по игрокам | `vaulttracker.search` |
| `/itemtop Alex АР` | Обе алмазные руды у игрока Alex | `vaulttracker.search` |
| `/itemtop Alex ИР` | Сумма обычной и глубинной изумрудной руды у игрока Alex | `vaulttracker.search` |
| `/vtrack` или `/vtrack help` | Краткая игровая справка | без отдельного права |
| `/vtrack mine` | Первые 10 своих зарегистрированных хранилищ | без отдельного права; только игрок |
| `/vtrack link <код>` | Одноразовая привязка своего персонажа к Telegram; код выдаёт бот в личке | `vaulttracker.link`; только игрок |
| `/vtrack find DIAMOND` | Топ владельцев предмета | `vaulttracker.search` |
| `/vtrack status` | Состояние локальной базы и MariaDB | `vaulttracker.admin` |
| `/vtrack rescan` | Ручная сверка зарегистрированных хранилищ в загруженных чанках | `vaulttracker.admin` |
| `/vtrack reload` | Перечитать настройки и перезапустить встроенного Telegram-бота | `vaulttracker.admin` |

`/vaulttracker` — полное имя `/vtrack`. Команда `/vtrack mine` предназначена для игрока: из консоли у неё нет собственного списка хранилищ. `/vtrack rescan` проверяет только зарегистрированные хранилища в уже загруженных чанках и не загружает мир принудительно.

Коды групп ресурсов:

| Код | Что суммируется |
| --- | --- |
| `AR` или `АР` | `DIAMOND_ORE` + `DEEPSLATE_DIAMOND_ORE` |
| `IR` или `ИР` | `EMERALD_ORE` + `DEEPSLATE_EMERALD_ORE` |

## Permissions

| Permission | По умолчанию | Что разрешает |
| --- | --- | --- |
| `vaulttracker.register` | всем (`true`) | Регистрировать хранилище табличкой `[vault]` |
| `vaulttracker.search` | всем (`true`) | Использовать `/topitem`, `/itemtop` и `/vtrack find` |
| `vaulttracker.link` | всем (`true`) | Привязать свой UUID к Telegram через `/vtrack link <код>` |
| `vaulttracker.admin` | только OP | Смотреть статус, запускать пересканирование, перезагружать настройки и редактировать чужую зарегистрированную табличку |

`vaulttracker.register` и `vaulttracker.search` доступны игрокам по умолчанию. `vaulttracker.admin` доступно операторам. Для LuckPerms обычным игрокам достаточно:

```text
/lp group default permission set vaulttracker.register true
/lp group default permission set vaulttracker.search true
```

Администраторам можно выдать управление без назначения OP:

```text
/lp group admin permission set vaulttracker.admin true
```

Чтобы запретить группе регистрацию или поиск:

```text
/lp group ИМЯ_ГРУППЫ permission set vaulttracker.register false
/lp group ИМЯ_ГРУППЫ permission set vaulttracker.search false
```

Названия предметов в результатах выводятся на русском. Количество от одного полного шалкера дополнительно показывается как эквивалент полных шалкеров и остатка. Это единица объёма: 27 обычных стаков предмета, а не число физических шалкеров.

## Поддерживаемые хранилища

Учитываются сундуки, двойные и медные сундуки, бочки, установленные шалкеры всех цветов, печи, плавильные печи, коптильни, воронки, раздатчики, выбрасыватели, варочные стойки, сборщики, резные книжные полки, полки, украшенные горшки, кафедры, проигрыватели и слоты костров.

Содержимое шалкеров и мешочков внутри хранилищ раскрывается рекурсивно, поэтому вложенные ресурсы входят в общую сумму. Книги учитываются по материалу: обычная, написанная, зачарованная и другие типы считаются отдельно. Название, автор, текст, зачарования, прочность и прочие метаданные предметов отдельные позиции пока не создают.

Эндер-сундуки не учитываются, поскольку их содержимое принадлежит конкретному игроку, а не блоку. Также не сканируются личные инвентари, вагонетки, лодки, существа и виртуальные хранилища других плагинов.

## Обновление каталога без периодического сканирования

Плагин не обходит все хранилища каждые 30 секунд. Каталог обновляется по событиям сервера: кликам и перетаскиванию предметов, закрытию инвентаря, переносу воронками, установке и разрушению блоков, взрывам, изменению таблички и загрузке чанка.

Выгруженные чанки принудительно не загружаются. Если внешний редактор или другой плагин меняет блоки без обычных событий Bukkit, данные обновятся при следующей загрузке чанка либо после ручной команды `/vtrack rescan`. Уничтожение таблички или хранилища прекращает его учёт. Изменение или очистка текста таблички сохраняет регистрацию, UUID владельца и ресурсы; отдельной проверки инвентаря и события охраны из-за текста не возникает. Собственные надписи сохраняются при обновлении каталога. Первая строка `[vault]` остаётся служебным маркером: при сверке она оформляется как надпись владельца.

## Встроенный Telegram-бот

### Привязка персонажа и охрана хранилищ

1. Откройте **личный чат** бота, отправьте `/menu` и нажмите **«Привязать персонажа»**.
2. Бот выдаст готовую команду `/vtrack link <код>`. Вставьте её в Minecraft, играя за своего персонажа. Код действует 10 минут и используется один раз; получение нового отменяет предыдущий. Не передавайте команду другим людям.
3. В боте нажмите **«Обновить кабинет»**. `/menu` и `/start` открывают кабинет с ником персонажа. Привязка хранится по UUID и переживает смену ника, перезапуск сервера и `/vtrack reload`.
4. **«Мои ресурсы»** показывает с перелистыванием все предметы в зарегистрированных вами хранилищах. Это каталог хранилищ, не инвентарь персонажа. Совпадающие ники других UUID не смешиваются.
5. **«Мои события · 2 дня»** открывает только события привязанного UUID за последние 48 часов. Имя другого игрока в личной истории не показывается. История накапливается с версии 0.7.0: старые события без сохранённого UUID доступны только в администраторской истории, чтобы не раскрыть чужие данные при совпадении ников.
6. **«⚙️ Настройки»** содержит включение/выключение личных уведомлений, срок уведомлений и две отдельные кнопки **«Применить тег»** и **«Сбросить тег»**. Применяется Minecraft-ник привязанного персонажа.

Тег ставится во всех уникальных группах из `chats` и `allowedChatIds`; несколько тем с одинаковым `chatId` считаются одной группой, поскольку Telegram-тег действует во всём чате, а не в отдельной теме. Игрок должен состоять в группе. Для обычного участника бот использует [`setChatMemberTag`](https://core.telegram.org/bots/api#setchatmembertag), поэтому назначьте боту право администратора **«Управление тегами»** (`can_manage_tags`). Игрок администратором от этого не становится и никаких прав не получает. Для игрока, который уже является администратором группы, используется его пользовательский титул: Telegram разрешает боту менять его только у администратора, назначенного самим ботом. После нажатия бот показывает отдельный результат для каждого `chatId`. Тег ограничен Telegram длиной 16 символов и не поддерживает эмодзи; обычный Minecraft-ник этим требованиям соответствует.

Время уведомлений: **«В том числе в игре»** — сообщения о новых изменениях приходят и во время игры, и после выхода; **«Сразу после выхода»** — только офлайн без ожидания; также доступны 2/5/15 минут, 1/6 часов, сутки, **2 дня**, неделя. **«Своё время»** включает ввод числа секунд (0–31536000, максимум 365 дней), например `172800` — двое суток. Ввод действует 10 минут, `/cancel` его отменяет. **«Как на сервере»** возвращает значение из `guard.yml`. Выбор сохраняется после перезапуска и `/vtrack reload`.

Кабинет организован по строкам:

| Строка | Раздел | Доступ |
| --- | --- | --- |
| 1 | Мои ресурсы | Привязанный игрок |
| 2 | Мои события за 2 дня | Привязанный игрок |
| 3 | Настройки игрока | Привязанный игрок |
| 4 | Настройки администратора | Telegram-администратор |
| 5 | События администраторов за 30 дней | Telegram-администратор |
| 6 | Супер администратор | Только ID из `guard.yml` |

Ниже остаётся кнопка поиска. Без привязки вместо личных разделов показана кнопка привязки; администраторские разделы доступны независимо от неё.

Личное время влияет только на уведомления владельцу. Для обычных администраторов остаётся время из `guard.yml`: игрок не может отложить их сообщения своей настройкой. Супер администратор может изменить только свой срок администраторских уведомлений, включая режим во время игры; сроки остальных администраторов не меняются. Изменение настройки применяется к новым изменениям хранилищ. Ранее произошедшие изменения не отправляются задним числом. В истории сохраняются события, для которых наступило хотя бы одно из этих условий; личные переключатели доставки не отключают запись таких событий.

Один Telegram-аккаунт связывается с одним персонажем, и наоборот. Перезаписать существующую привязку новой командой нельзя. Коды не сохраняются после перезапуска; уже завершённые привязки сохраняются. Плагин доверяет UUID вошедшего игрока, поэтому на сервере должна работать штатная авторизация игроков.

Новый файл `plugins/VaultTracker/guard.yml` создаётся автоматически:

```yaml
enabled: true
offline-seconds: 120
superAdminUserId: 0
```

`offline-seconds` — сколько секунд игрок должен отсутствовать после выхода, прежде чем изменения его хранилища попадут в охрану. `120` — две минуты, `0` — сразу после выхода. Допустимый диапазон: 0–31536000 секунд. После изменения выполните `/vtrack reload`. `enabled: false` отключает фиксацию и отправку событий охраны, сохраняя привязки и историю.

Охрана получает **уже готовые изменения каталога по игровым событиям**: действия с инвентарём, работа воронок, разрушение контейнера и другие события, которые поддерживает каталог. Она не добавляет обход сундуков, сканирование мира или загрузку чанков. Сравнение количеств выполняется в памяти; запись истории и сетевые запросы — отдельными фоновыми обработчиками. Неизменившийся состав, первая регистрация и восстановление каталога сами по себе уведомлений не создают.

Событие записывается, когда выполняется хотя бы одно условие уведомлений владельца, администратора или супер администратора. Режим «В том числе в игре» учитывает изменения и при онлайн-владельце. После этого добавление и уменьшение количества вещей фиксируются со знаком `+`/`−`, временем обнаружения и координатами контейнера. Изменения, которые владелец сам сделал в своём хранилище, не создают событие и не отправляют уведомления: это обычная работа с вещами. В уведомлении администратору и подробной истории указывается другой игрок, чьё действие вызвало изменение. Плагин определяет игрока по UUID при клике, перетаскивании, закрытии инвентаря, прямом взаимодействии и разрушении блока. Для воронок, взрывов, механизмов, сторонних плагинов и неоднозначных изменений выводится `Кто изменил: не определено`; это честнее, чем приписывать действие последнему посетителю. Удаление таблички/контейнера или отмена регистрации отмечаются как **снятие хранилища с учёта**, а не как доказанная кража. Каталог учитывает типы и количества предметов: перестановка слотов или изменение NBT при прежних количествах не являются отдельным событием.
Изменения, инициированные автоматическими блоками (воронки, крафтеры, печи, варочные стойки, раздатчики и перемещения между инвентарями), обновляют каталог без создания событий и уведомлений в Telegram, чтобы защита не флудила. Действие игрока с подтверждённой атрибуцией сохраняет обычное уведомление даже рядом с автоматикой.

В сообщениях и истории выводится настоящее имя мира сервера (например, `world`, `world_nether` или имя вашего мира) и строка `Координаты: -3779 64 -305`. UUID заменяется именем также при просмотре старой истории и отправке ещё не доставленных сообщений, если мир известен серверу. Уже отправленные сообщения не редактируются. Имена миров сохраняются локально, поэтому остаются доступными после выгрузки мира. Если имя старого удалённого мира неизвестно, выводится «неизвестный мир».

Если чанк не загружен или сторонний плагин меняет инвентарь без Bukkit-события, изменение обнаружится при следующем штатном обновлении каталога; дополнительного сканирования охрана не запускает. После первого запуска охраны для владельцев с неизвестным временем выхода отсчёт начинается от запуска плагина. При аварийном завершении сервера прежние онлайн-игроки также получают этот период ожидания.

Уведомление отправляется в личку привязанному владельцу и пользователям из `adminUserIds` в существующем `telegram.yml`, с учётом их отдельных переключателей. Администратор получает события и для непривязанных владельцев. Если администратор одновременно владелец, одинаковое событие не дублируется; отключение одного канала не отключает другой. Каждый получатель должен открыть личный чат бота и нажать `/start` — бот не может первым начать переписку.

Администратору не обязательно привязывать персонажа. В разделе «Функции администратора» доступны уведомления, онлайн/офлайн список игроков и история событий с поиском. Действия над игроками определяются переключателями супер администратора; права повторно проверяются перед выполнением.

### Супер администратор и управление сервером

Основной Telegram ID задаётся в `guard.yml`, поле `superAdminUserId`. В меню «Администраторы бота» можно добавлять и удалять дополнительные роли, включая супер администраторов, и переключать действия обычных администраторов. Основной супер администратор и собственная супер роль защищены от удаления через меню. Роли сохраняются в `guard-data.mv.db`.

Списки открываются с онлайн-игроков; есть офлайн, поиск по части ника и страницы. Карточка игрока содержит сведения и действия: инвентарь, эндер-сундук, бан на 5 минут, кик, разбан, лечение, убийство, ремонт, размер, скорости, телепортация, сообщение в игровой чат, группа LuckPerms admin и выдача/снятие OP. Офлайн-инвентари читаются из последнего сохранения playerdata. Изменения размера и скорости поддерживают своё значение. Телепортация на координаты принимает `x y z` в текущем мире игрока.

Действия требуют подтверждения. Бан не сокращает существующий бан; сообщение в игровой чат не выполняется как команда. Супер администратор сохраняет все функции независимо от переключателей обычных администраторов. Его действия VaultTracker не записывает в журнал модерации. Сторонние плагины могут вести собственный журнал.

Подробная структура меню и установка: [инструкция 0.9.0](outputs/Установка-0.9.0.md).

### Быстрые нажатия и восстановление бота

Ошибки Telegram `message is not modified`, `query is too old` и `query ID is invalid` не запускают переподключение. Ошибка обработки отдельного сообщения не останавливает получение следующих. Кнопки кабинета и пагинации не имеют временного TTL во время работы бота; для защиты памяти хранятся последние 2048 действий на пользователя и 4096 поисковых сессий. После перезапуска процесса старые callback-кнопки требуют повторного открытия меню. Номер обновления сохраняется **до** выполнения действия, поэтому неудачный ответ Telegram не приводит к повторному бану, кику или переключению настройки. Если процесс аварийно завершится между сохранением номера и действием, запрос может не выполниться: откройте `/menu` и проверьте результат перед повторением.

Для восстановления ранее остановившегося бота достаточно `/vtrack reload` в игре или `vtrack reload` в консоли. Команда `vtracker reload` не существует. После замены JAR необходим полный перезапуск сервера.

История записывается независимо от личных переключателей. Старые события и недоставленные сообщения удаляются по сроку 30 дней. Ошибки доставки не удаляют событие: сообщение повторяется через 5 минут. Несколько небольших событий для одного получателя могут прийти одним сообщением. При сбое между отправкой Telegram и сохранением подтверждения возможна повторная доставка; номер события позволяет её распознать.

Привязки, личные переключатели, время выхода, история и очередь доставки находятся в **`guard-data.mv.db`**, отдельно от каталога. Сохраняйте этот файл в резервной копии при остановленном сервере. Данные охраны локальны этому серверу и не синхронизируются через MariaDB. **Существующий `telegram.yml` не перезаписывается**, заново вводить токен, прокси и чаты не нужно.

### Личное меню поиска

Откройте личную переписку с ботом и отправьте `/start` или `/menu`.

1. Нажмите **«🔎 Поиск»**.
2. Выберите **«👤 Игрок»** или **«📦 Предмет»**.
3. Листайте список кнопками **«Назад» / «Вперёд»** и нажмите нужный ник или предмет.
4. Отправьте часть ника или названия предмета, чтобы отфильтровать список. Например: `Алм`, `алма`, `diam`, `алм глуб` или `lex`. Поиск не зависит от регистра, для предметов проверяются русское название и английский ID. После ввода, даже полного названия, выберите нужную кнопку.
5. Отфильтрованный список и результаты листаются кнопками. **«К списку»** сохраняет фильтр и страницу, **«Сбросить фильтр»** возвращает весь список. Новый текст заменяет прежний фильтр. **«Поиск»** меняет режим, **«Меню»** завершает ввод.

Список игроков содержит владельцев зарегистрированных хранилищ, включая игроков не в сети. Предметы берутся из каталога ресурсов; дополнительно доступны группы `АР/AR` и `ИР/IR`. Если совпадений нет, можно ввести другой запрос или сбросить фильтр. Ник, совпадающий с предметом (например, `Stone`), в режиме «Игрок» ищется именно как ник. Прямые команды `/item предмет` по-прежнему сразу показывают топ.
Во всех списках игроков в кабинете супер-администратора доступна кнопка «Поиск»: введите любую часть ника, после чего отфильтрованный список можно листать дальше.

Личное меню доступно любому пользователю, открывшему переписку с ботом. Ограничения `chats` и `allowedChatIds` продолжают управлять групповыми чатами. Административные `/status` и `/items` требуют текущей роли администратора бота, с учётом `adminUserIds`, изменений из панели и роли супер администратора.

Свободный текст используется для поиска только в личной переписке и только на экране списка игроков или предметов. В групповых темах бот по-прежнему игнорирует обычную беседу. `/cancel` отменяет ожидание ввода. Через 30 минут без действий или после перезапуска сессия закрывается — откройте `/menu` заново. Кнопки прежнего экрана становятся недействительными при открытии нового.

В личке меню и результаты автоматически не удаляются. Кнопки редактируют текущий ответ; текстовый запрос создаёт новый ответ. В группах действует прежнее время удаления `messageLifetimeSeconds`. Для личного меню используются существующие настройки `pageSize`, новый конфиг заполнять не нужно.

Кнопки предметов и ответы Telegram содержат обычные emoji: 💎 алмазы и алмазные руды, 🟢 изумруды, 🔩 железо, 📚 книги, 🪵 дерево, ⛏️ кирки, ⚔️ мечи. Это условные значки категорий, а не Minecraft-текстуры. Для остальных предметов используется 📦. Premium, загрузка картинок и новые настройки не нужны. Точные текстуры в кнопках потребовали бы custom emoji; отдельные карточки с картинками — другого оформления сообщений.

### Порядок настройки

1. Установите новый JAR и запустите сервер. Если `plugins/VaultTracker/telegram.yml` отсутствует, плагин создаст стандартный файл в самом начале запуска и напечатает его полный путь в консоли. Существующий файл не перезаписывается.
2. В Telegram откройте `@BotFather`, выполните `/newbot`, задайте имя и username бота. Скопируйте полученный токен.
3. Добавьте созданного бота в нужную группу. Для обычных команд права администратора ему не требуются. Для удаления команд выдайте «Удаление сообщений», а для кнопок применения/сброса ника игрока — новое право «Управление тегами».
4. В `telegram.yml` вставьте токен, поставьте `enabled: true` и настройте прокси. Для прямого подключения укажите `type: "none"`. Сохраните файл и выполните в игре `/vtrack reload` от имени оператора.
5. Оставьте ограничения `chats` и `allowedChatIds` на месте: команда `/id` выводит данные в консоль даже из ещё не разрешённой темы.
6. Откройте в Telegram именно ту тему, где должен работать бот, и отправьте `/id`. Если Telegram не предлагает команду или в группе несколько ботов, отправьте `/id@username_вашего_бота`.
7. Откройте консоль Minecraft-сервера: там появится блок `chats` с `chatId`/`topicId` и `adminUserIds` с ID отправителя. Скопируйте нужные значения в существующий `telegram.yml`, сохраните файл и выполните `/vtrack reload`. Ответ с ID в Telegram не отправляется.
8. Отправьте `/item алмаз` в разрешённой теме. Администратор также может проверить `/status`. В другой теме бот ничего не отвечает, а командное сообщение сразу удаляет.

Команда `/id` ничего не настраивает сама: она выводит ID отправителя, чата и текущей темы только в консоль сервера (и серверный лог). Исходное сообщение `/id` удаляется, если у бота есть право удаления. Каждый будущий администратор может выполнить `/id`; владелец сервера решает, чей ID добавить в `adminUserIds`. Токен и пароль прокси в этот вывод не входят.

Для ваших значений готовый блок выглядит так:

```yaml
enabled: true
token: "НОВЫЙ_ТОКЕН_BOTFATHER"

# Если chats тоже пуст, разрешает команды во всех группах.
allowedChatIds: []

# Пользователи Telegram с доступом к административным командам.
adminUserIds:
  - 123456789

# Групповые команды работают только в заданных чатах и темах.
chats:
  - isDefault: true
    chatId: -1000000000000
    topicId: 12345

pageSize: 8
pollTimeoutSeconds: 30
messageLifetimeSeconds: 300

advanced:
  botApiUrl: "https://api.telegram.org"
  proxy:
    # Поддерживаются: none, socks5, http
    type: "socks5"
    host: "127.0.0.1"
    port: 1080
    username: ""
    password: ""
  connectionRetry:
    # Значение меньше 1 означает бесконечное число попыток.
    maxAttempts: 10
    initialDelay: 1000
    maxDelay: 300000

# Версия формата. Не меняйте вручную.
version: 4
```

В групповых чатах обычные сообщения бот игнорирует. Обрабатываются только команды VaultTracker: `/item`, `/topitem`, `/itemtop`, `/start`, `/help`, `/id`, `/status`, `/items`; в личке дополнительно доступны `/menu`, `/search`, `/cancel`. Неизвестные команды, например `/list` плагина TGBridge, не вызывают ответа и не удаляются. При указании `@username` бот проверяет адресата: `/item@ДругойБот` и `/id@ДругойБот` также игнорируются. Имя своего бота определяется автоматически при подключении. В личке чужие команды не сбрасывают открытый поиск.

В группах бот принимает команды только в указанных парах `chatId + topicId` и отвечает в той же теме. В запрещённой теме он молча игнорирует и удаляет только свои команды. В разрешённой теме сообщения с командами VaultTracker удаляются после ответа, включая `/item алмаз`, `/item Ник алмаз`, `/topitem` и `/itemtop` с аргументами. Ответы бота удаляются отдельно по настройке `messageLifetimeSeconds`. Для удаления сообщений боту нужно выдать в группе право администратора «Удаление сообщений». Для обычного чата без тем используется `topicId: 0`. Можно перечислить несколько тем; только одна запись может иметь `isDefault: true`. Это основная тема для будущих автоматических уведомлений.

Если `chats` пуст, продолжает действовать старый список `allowedChatIds`, разрешающий все темы указанного чата. Если оба списка пусты, бот доступен всем. `/id` работает независимо от этих ограничений и прав администратора Telegram-бота: данные идут только в консоль сервера, доступ к каталогу при этом не открывается.

Обычным пользователям доступна одна команда с теми же режимами, что в игре:

- `/item алмаз` или `/item diamond` — топ игроков по конкретному ресурсу;
- `/item железный слиток` — русское название из нескольких слов;
- `/item Alex` — все ресурсы игрока;
- `/item Alex алмаз` — количество конкретного ресурса у игрока;
- `/item player Stone` — явный поиск игрока, если ник совпадает с названием предмета.
- `/itemtop АР` / `/itemtop AR` — общий топ по обычной и глубинной алмазной руде;
- `/itemtop Alex ИР` / `/itemtop Alex IR` — суммарное количество двух видов изумрудной руды у Alex.

Старая команда `/topitem` продолжает работать с теми же русскими и английскими запросами. В меню команд группы показывается `/item`, а в личной переписке доступны также `/menu`, `/search`, `/cancel` и `/help`.

Списки выводятся по `pageSize` строк. Кнопки «Назад» и «Вперёд» редактируют одно сообщение и не засоряют тему. Нажимать их может только автор запроса. В группах ответ бота автоматически удаляется через `messageLifetimeSeconds` секунд, по умолчанию через 5 минут. После удаления или перезапуска бота запрос нужно выполнить заново.

### Все команды Telegram

| Команда | Кто может использовать | Назначение |
| --- | --- | --- |
| `/start` или `/help` | все пользователи личного чата; разрешённые пользователи группы | В личке — меню с кнопкой поиска; в группе — справка |
| `/menu` | личный чат | Открыть начальное меню |
| `/search` | личный чат | Выбрать поиск игрока или предмета |
| `/cancel` | личный чат | Отменить ввод и вернуться в меню |
| `/id` или `/id@имя_бота` | любой отправитель, в том числе из ещё не разрешённой темы | Вывести `chatId`, `topicId` и ID отправителя для `adminUserIds` только в консоль сервера; удалить команду без ответа в Telegram |
| `/item предмет` | все разрешённые пользователи | Топ игроков по предмету |
| `/item Ник` | все разрешённые пользователи | Все ресурсы игрока |
| `/item Ник предмет` | все разрешённые пользователи | Количество предмета у игрока |
| `/item player Stone` | все разрешённые пользователи | Явно искать игрока, если ник похож на предмет |
| `/itemtop АР` / `/itemtop AR` | все разрешённые пользователи | Топ по сумме двух алмазных руд |
| `/itemtop ИР` / `/itemtop IR` | все разрешённые пользователи | Топ по сумме двух изумрудных руд |
| `/itemtop Ник АР` | все разрешённые пользователи | Обе алмазные руды у игрока |
| `/itemtop Ник ИР` | все разрешённые пользователи | Обе изумрудные руды у игрока |
| `/topitem ...` | все разрешённые пользователи | Полный алиас `/item` с теми же режимами |
| `/items` | только `adminUserIds` | Все предметы во всём каталоге, с постраничным выводом |
| `/status` | только `adminUserIds` | Состояние хранилища данных и число зарегистрированных хранилищ |

Игровые permissions не управляют Telegram. Доступ к темам задаётся через `chats`/`allowedChatIds`, а доступ к административным разделам бота — через `adminUserIds` в `telegram.yml`. Права самого бота внутри Telegram-группы назначаются средствами Telegram: «Удаление сообщений» нужно для очистки команд, «Управление тегами» — для применения и сброса ника обычного игрока.

Бот читает уже загруженный локальный каталог плагина и не требует отдельного процесса или отдельного пользователя MariaDB. Токен можно передать переменной окружения `VAULT_TELEGRAM_TOKEN`, логин и пароль прокси — `VAULT_TELEGRAM_PROXY_USERNAME` и `VAULT_TELEGRAM_PROXY_PASSWORD`. Настоящие секреты не добавляйте в Git.

## Установка и обновление

1. Остановите сервер и сохраните резервную копию папки `plugins/VaultTracker`.
2. Удалите старый JAR VaultTracker и поместите в `plugins` только `VaultTracker-0.9.0.jar`.
3. Запустите сервер. Существующие `config.yml`, `telegram.yml`, `server-id`, `cache-*.mv.db` и `guard-data.mv.db` сохраняются. При первом обновлении создастся `guard.yml`.
4. При необходимости измените `telegram.yml` и выполните `/vtrack reload`. После обновления самого JAR всё равно требуется обычный перезапуск сервера.

В папке плагина находится локальная база `cache-<server-id>.mv.db`. Сохраняйте её в резервной копии вместе с миром. Она содержит регистрации, последние остатки и очередь изменений для MariaDB.

## MariaDB

MariaDB включается в `config.yml` и используется как удалённая копия каталога. Плагину нужны права `CREATE`, `INDEX`, `SELECT`, `INSERT`, `UPDATE` и `DELETE` в выделенной базе. Вместо пароля в файле можно задать `VAULT_DB_PASSWORD`.

Создаются таблицы `vt2_vaults` и `vt2_items`. Отключение MariaDB не останавливает локальный учёт. После восстановления подключения накопленные изменения отправляются автоматически. У разных серверов должны быть разные `server-id`.

## Сборка и проверка

Откройте проект с JDK 25 и запустите `./gradlew build` либо `.\\gradlew.bat build` в Windows. Устанавливать нужно итоговый `build/libs/VaultTracker-0.12.1-folia26.jar`; файлы `*-plain.jar` и `*-smoke.jar` серверу не нужны.

Автоматические тесты проверяют локальный каталог, MariaDB-проекцию, поддерживаемые хранилища, вложенные контейнеры, команды, русские названия, конфигурацию Telegram и обработку его команд. Реальное подключение к пользовательскому Telegram-прокси и MariaDB тестами не выполняется.
