# VaultTracker 0.2.4

Каталог ресурсов из отмеченных сундуков для Folia/Luminol 1.21.11 и MariaDB. Java 21 или совместимая более новая версия. Telegram-бот — следующий отдельный этап; запрос для поиска уже готов.

## Использование

Поставьте обычную табличку сверху на хранилище или прикрепите её сбоку и напишите `[vault]` на первой строке лицевой стороны. Одна табличка учитывает обе половины двойного сундука. Повторная регистрация того же сундука отклоняется. После регистрации три строки: «Собственность», «игрока», ник. Регистрация сохраняется после замены надписи и перезапуска.

Владелец записи — игрок, написавший маркер. Сохраняются UUID и имя. Имя обновляется при входе игрока с тем же UUID. В offline-mode смена ника может менять UUID; такую смену нельзя автоматически считать тем же игроком.

| Команда | Назначение |
| --- | --- |
| `/topitem diamond` | Топ владельцев ресурса; `daimond` тоже распознаётся |
| `/vtrack mine` | Ваши зарегистрированные сундуки, первые 10 |
| `/vtrack find DIAMOND` | Игроки и сумма алмазов по их сундукам, первые 20 |
| `/vtrack status` | Состояние сохранения и MariaDB, для администратора |
| `/vtrack rescan` | Сверка загруженных сундуков, для администратора |

Команды поиска и просмотра своих сундуков постоянные и доступны обычным игрокам; OP не требуется. Поиск показывает последние известные остатки этого сервера. Telegram-бот остаётся отдельным этапом и будет использовать MariaDB.

В консоли команды вводятся без `/`. Предметы указываются английскими идентификаторами, например `IRON_INGOT`, `STONE`, `OAK_LOG`. Есть автодополнение.

## Поддерживаемые хранилища

Сундуки (включая двойные и медные), бочки, установленные шалкеры всех цветов, печи, плавильные печи, коптильни, воронки, раздатчики, выбрасыватели, варочные стойки, сборщики, резные книжные полки, полки, украшенные горшки, кафедры, проигрыватели и слоты костров. Считается содержимое, а не сам установленный блок. Шалкеры и мешочки внутри инвентаря раскрываются при подсчёте.

Эндер-сундуки не поддерживаются: у них личный инвентарь игрока, а не инвентарь блока. Также это не учёт вагонеток, лодок, существ и виртуальных хранилищ сторонних плагинов. Табличка должна непосредственно опираться на хранилище: обычная сверху или сбоку, подвесная — снизу. Боковые подвесные таблички на перекладине не поддерживаются.

При переносе установленного шалкера его прежняя регистрация снимается. На новом месте нужна новая табличка. Права прежние: vaulttracker.register для регистрации, vaulttracker.search для поиска.

## Просмотр ресурсов игрока (0.2.4)

- /topitem diamond — прежний топ владельцев предмета.
- /topitem Alex — все ресурсы игрока Alex из зарегистрированных хранилищ.
- /topitem Alex 2 — вторая страница; по 8 строк, кнопки Назад/Вперёд в чате.
- /topitem Alex diamond — количество алмазов у Alex; опечатки diamon и daimond поддерживаются.
- /topitem player Stone — явный выбор игрока, если ник совпадает с названием предмета.

Права прежние: vaulttracker.search. Игроку не обязательно быть онлайн. Названия предметов русские независимо от языка клиента, английский ID доступен при наведении на строку. Русский словарь Minecraft 1.21.11 встроен в JAR, сеть при запуске не требуется. Информация относится к последним известным остаткам отмеченных хранилищ, включая вложенные шалкеры и мешочки. Личный инвентарь игрока не сканируется. Список отсортирован по количеству, при равенстве — по ID предмета. Новая страница получает свежие данные; если число страниц сократилось, команда сообщит допустимый диапазон.

## Обновления

Учитываются клики, перетаскивание, закрытие сундука, перенос воронками, постановка соседнего сундука, разрушение и взрывы. Раз в 30 секунд дополнительно сверяются загруженные сундуки. Снятие таблички или замена первой строки на другой текст (в том числе пустую строку) прекращает учёт. Повторный ввод [vault] сохраняет владельца. Старые зарегистрированные таблички автоматически получают новый вид при сверке загруженного чанка.

Разрушение половины двойного сундука под табличкой прекращает учёт всего хранилища; разрушение другой половины оставляет учёт сохранившейся половины.

Если сторонний плагин/редактор объединит два отдельно зарегистрированных хранилища, обе регистрации снимаются, чтобы не приписывать чужие ресурсы одному владельцу. После этого нужно оставить один маркер и заново написать `[vault]`.

## Установка

Обновление с 0.2.0: остановите сервер, сохраните резервную копию JAR и папки `plugins/VaultTracker`, замените старый JAR на `VaultTracker-0.2.3.jar` и запустите сервер. В `plugins` должна остаться одна версия VaultTracker. Существующие `config.yml`, `server-id` и файлы `cache-*.mv.db` сохраняются. Старые зарегистрированные таблички обновятся при загрузке и сверке чанка; `/vtrack rescan` запускает сверку вручную.

1. Остановите тестовый сервер и сделайте резервную копию.
2. Поместите **только** `build/libs/VaultTracker-0.2.3.jar` в `plugins`. Файлы `*-plain.jar` и `*-smoke.jar` устанавливать не нужно.
3. В `plugins/VaultTracker/config.yml` укажите пароль `vault_plugin` и включите `database.enabled: true`. Когда Folia и MariaDB на одной машине, используйте `127.0.0.1`.
4. Запустите сервер. Ожидаются сообщения «Локальный каталог загружен» и «MariaDB подключена».

Вместо пароля в файле можно задать переменную окружения `VAULT_DB_PASSWORD`. Файл с настоящим паролем храните только на сервере.

У тестового и основного серверов должны быть разные `server-id`. Один ID не должен одновременно использоваться двумя экземплярами. Для существующего каталога ID менять нельзя без переноса данных.

## Сохранение и сбои

В папке плагина находится `cache-test.mv.db` (имя зависит от server-id). Это локальное хранилище регистраций, последних остатков и очереди неотправленных изменений. **Сохраняйте этот файл в резервной копии вместе с миром и конфигурацией. Не удаляйте его как временный кеш.**

Отдельный поток записывает изменения на диск примерно каждые 250 мс. Другой поток отправляет их в MariaDB примерно раз в 2 секунды. Отключение MariaDB не блокирует локальную запись. После восстановления связи отправка продолжается автоматически, в том числе после перезапуска.

При обычной остановке ожидается сохранение очереди. При аварии процесса/питания до записи на диск последние изменения в памяти могут потеряться. Остатки зарегистрированных загруженных сундуков исправляются сверкой; потерянный новый маркер потребуется зарегистрировать повторно.

MariaDB содержит проекцию локального каталога. Восстановление регистраций только из MariaDB при потере локального файла пока не реализовано. При запуске локальные записи отправляются повторно; это не увеличивает остатки.

Выгруженные чанки принудительно не загружаются: сохраняются последние известные остатки и время проверки. Изменения внешним редактором будут замечены при загрузке чанка. Содержимое шалкербоксов всех цветов и мешочков рекурсивно включается в сумму ресурсов, сами контейнеры также считаются; зачарования/имена/прочность отдельно не учитываются — группировка по типу предмета.

## MariaDB и будущий бот

Создаются таблицы `vt2_vaults` и `vt2_items` в указанной базе. CoreProtect не используется. Старые таблицы прототипа `vt_vaults`/`vt_items`, если они были, автоматически не мигрируются и не удаляются.

При снятии с учёта устанавливается `active=false`, строки предметов удаляются в той же транзакции. `checked_at_ms` — время проверки в миллисекундах Unix. Боту следует показывать актуальность данных.

Запрос для поиска находится в `sql/search.sql`. В программе вместо литерала DIAMOND нужно использовать параметр запроса. Боту достаточно отдельного пользователя с SELECT на двух таблицах. Плагину нужны CREATE, INDEX, SELECT, INSERT, UPDATE, DELETE в базе каталога.

## Права

`vaulttracker.register` и `vaulttracker.search` доступны игрокам по умолчанию, `vaulttracker.admin` — операторам. Плагин уважает отменённые события, но не является системой приватов. Владелец записи не обязательно является владельцем региона; совместимость с конкретным плагином приватов нужно проверить отдельно.

## Проверка и сборка

Автоматические тесты охватывают подсчёт, двойные сундуки, конфликты владельцев, параллельные регистрации, поздние события, смену имени, восстановление локальных данных, подтверждение устаревшей версии, транзакционный откат и повторную отправку. SQL-тесты работают на H2 в режиме MySQL и не заменяют проверку реальной MariaDB.

Для предыдущей версии 0.2.1 были пройдены 23 модульных теста и 23 проверки на отдельном локальном Luminol 1.21.11: замена маркера ником, повторная сверка, смена имени владельца, двойные сундуки во всех направлениях, события воронки, опустошение и разрушение сундука. Проверка подключения новой сборки к пользовательской MariaDB не выполнялась.

Перед основным сервером проверьте в игре: 10 алмазов → забрать 3 → второй отмеченный сундук → воронка → снятие таблички → взрыв → перезапуск. Двойной сундук должен считаться один раз. После временного отключения MariaDB изменения должны догнаться.

Откройте проект в IntelliJ IDEA, выберите JDK 21 и Gradle Wrapper. Сборка: `.\gradlew.bat build`.

`src/smoke` — отдельный тестовый плагин, который меняет блоки одноразового локального мира smoke_world на порту 25579 и останавливает тестовый процесс. **Его нельзя устанавливать на пользовательский сервер.** Сборка этого теста: `.\gradlew.bat smokeJar`.



Для 0.2.3: 33 автоматических теста и 85 проверок на отдельном Luminol 1.21.11 прошли. Проверены 31 вид/цвет блоков с инвентарём, их снятие с учёта, двойные сундуки, таблички и события воронки. Реальная пользовательская MariaDB в этом прогоне не подключалась.



Для 0.2.4: 40 автоматических тестов (ошибок: 0) и 90 проверок на локальном Luminol 1.21.11 прошли. Проверены полнота русских названий, страницы и команды кнопок, поиск предмета у игрока, а также ранее поддержанные хранилища. Telegram-бот в эту сборку не входит.


Версия 0.2.5: /topitem показывает точное количество и эквивалент в полных шалкерах с остатком, начиная с одного полного шалкера. Вместимость — 27 слотов с обычным максимальным размером стака данного материала (64, 16 или 1). Это единица объёма, а не число физических шалкеров, в которых лежат ресурсы. Для самих шалкербоксов пересчёт не применяется. Учёт отдельных видов книг пока не добавлен; они продолжают учитываться по материалу.
