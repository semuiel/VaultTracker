# VaultTracker 0.4.2

Каталог ресурсов из отмеченных хранилищ для Folia/Luminol 1.21.11. Требуется Java 21 или новее. В плагин встроен Telegram-бот с прямым подключением, SOCKS5 и HTTP-прокси. MariaDB необязательна: игровой каталог и встроенный бот работают с локальной базой плагина.

## Использование

Поставьте обычную табличку сверху на хранилище или прикрепите её сбоку и напишите `[vault]` на первой строке лицевой стороны. Для подвесной таблички хранилище должно находиться над ней. После регистрации на табличке появятся строки «Собственность», «игрока» и ник владельца.

Одна табличка учитывает обе половины двойного сундука. Сохраняются UUID и имя владельца. Повторная регистрация того же хранилища отклоняется.

| Команда | Назначение | Право |
| --- | --- | --- |
| `/topitem diamond` | Топ владельцев предмета; опечатки `diamon` и `daimond` распознаются | `vaulttracker.search` |
| `/topitem Alex` | Все ресурсы игрока, по 8 строк на странице | `vaulttracker.search` |
| `/topitem Alex 2` | Вторая страница списка с кнопками «Назад» и «Вперёд» | `vaulttracker.search` |
| `/topitem Alex diamond` | Количество конкретного предмета у игрока | `vaulttracker.search` |
| `/vtrack mine` | Первые 10 своих зарегистрированных хранилищ | `vaulttracker.search` |
| `/vtrack find DIAMOND` | Топ владельцев предмета | `vaulttracker.search` |
| `/vtrack status` | Состояние локальной базы и MariaDB | `vaulttracker.admin` |
| `/vtrack rescan` | Ручная сверка зарегистрированных хранилищ в загруженных чанках | `vaulttracker.admin` |
| `/vtrack reload` | Перечитать настройки и перезапустить встроенного Telegram-бота | `vaulttracker.admin` |

`vaulttracker.register` и `vaulttracker.search` доступны игрокам по умолчанию. `vaulttracker.admin` доступно операторам. Для LuckPerms обычным игрокам достаточно:

```text
/lp group default permission set vaulttracker.register true
/lp group default permission set vaulttracker.search true
```

Названия предметов в результатах выводятся на русском. Количество от одного полного шалкера дополнительно показывается как эквивалент полных шалкеров и остатка. Это единица объёма: 27 обычных стаков предмета, а не число физических шалкеров.

## Поддерживаемые хранилища

Учитываются сундуки, двойные и медные сундуки, бочки, установленные шалкеры всех цветов, печи, плавильные печи, коптильни, воронки, раздатчики, выбрасыватели, варочные стойки, сборщики, резные книжные полки, полки, украшенные горшки, кафедры, проигрыватели и слоты костров.

Содержимое шалкеров и мешочков внутри хранилищ раскрывается рекурсивно, поэтому вложенные ресурсы входят в общую сумму. Книги учитываются по материалу: обычная, написанная, зачарованная и другие типы считаются отдельно. Название, автор, текст, зачарования, прочность и прочие метаданные предметов отдельные позиции пока не создают.

Эндер-сундуки не учитываются, поскольку их содержимое принадлежит конкретному игроку, а не блоку. Также не сканируются личные инвентари, вагонетки, лодки, существа и виртуальные хранилища других плагинов.

## Обновление каталога без периодического сканирования

Плагин не обходит все хранилища каждые 30 секунд. Каталог обновляется по событиям сервера: кликам и перетаскиванию предметов, закрытию инвентаря, переносу воронками, установке и разрушению блоков, взрывам, изменению таблички и загрузке чанка.

Выгруженные чанки принудительно не загружаются. Если внешний редактор или другой плагин меняет блоки без обычных событий Bukkit, данные обновятся при следующей загрузке чанка либо после ручной команды `/vtrack rescan`. Снятие таблички или замена её первой строки прекращает учёт.

## Встроенный Telegram-бот

### Порядок настройки

1. Установите новый JAR и один раз запустите сервер. Плагин создаст файл `plugins/VaultTracker/telegram.yml`.
2. В Telegram откройте `@BotFather`, выполните `/newbot`, задайте имя и username бота. Скопируйте полученный токен.
3. Добавьте созданного бота в нужную группу. Для обычных команд права администратора ему не требуются.
4. В `telegram.yml` вставьте токен, поставьте `enabled: true` и настройте прокси. Для прямого подключения укажите `type: "none"`. Сохраните файл и выполните в игре `/vtrack reload` от имени оператора.
5. Чтобы сначала узнать номера, временно оставьте `chats: []` и `allowedChatIds: []`.
6. Откройте в Telegram именно ту тему, где должен работать бот, и отправьте `/id`. Если Telegram не предлагает команду или в группе несколько ботов, отправьте `/id@username_вашего_бота`.
7. Бот ответит тремя строками: `ID пользователя`, `ID этого чата` и `ID этой темы`. Перенесите чат и тему в `chats`, ID администраторов — в `adminUserIds`, сохраните файл и снова выполните `/vtrack reload`.
8. Отправьте `/item алмаз` в разрешённой теме. Администратор также может проверить `/status`. В другой теме бот ничего не отвечает, а командное сообщение сразу удаляет.

Команда `/id` ничего не настраивает сама: она показывает Telegram ID отправителя, чата и текущей темы. Её нужно вводить внутри нужной темы, а затем вручную записать ответ в `telegram.yml`. Каждый будущий администратор должен выполнить `/id`, чтобы узнать свой пользовательский ID.

Для ваших значений готовый блок выглядит так:

```yaml
enabled: true
token: "НОВЫЙ_ТОКЕН_BOTFATHER"

# Пустой список разрешает доступ всем пользователям бота.
allowedChatIds: []

# Пользователи Telegram с доступом к административным командам.
adminUserIds:
  - 123456789

# Команды работают только в заданных чатах и темах.
chats:
  - isDefault: true
    chatId: -1000000000000
    topicId: 12345

pageSize: 8
pollTimeoutSeconds: 30
messageLifetimeSeconds: 300

advanced:
  botApiUrl: "https://api.telegram.org"
  proxy:
    # Поддерживаются: none, socks5, http
    type: "socks5"
    host: "127.0.0.1"
    port: 1080
    username: ""
    password: ""
  connectionRetry:
    # Значение меньше 1 означает бесконечное число попыток.
    maxAttempts: 10
    initialDelay: 1000
    maxDelay: 300000

# Версия формата. Не меняйте вручную.
version: 4
```

Бот принимает команды только в указанных парах `chatId + topicId` и отвечает в той же теме. В запрещённой теме он молча игнорирует и удаляет любую команду. В разрешённой теме сообщения служебных команд (`/id`, `/status`, `/items`, `/help`) удаляются после обработки, а запросы `/item`, `/topitem` и `/itemtop` остаются в чате. Для удаления сообщений боту нужно выдать в группе право администратора «Удаление сообщений». Для обычного чата без тем используется `topicId: 0`. Можно перечислить несколько тем; только одна запись может иметь `isDefault: true`. Это основная тема для будущих автоматических уведомлений.

Если `chats` пуст, продолжает действовать старый список `allowedChatIds`, разрешающий все темы указанного чата. Если оба списка пусты, бот доступен всем. При заполненном `chats` команда `/id` в запрещённой теме также будет удалена; для получения ID временно очистите `chats`, выполните `/id`, затем верните ограничение.

Обычным пользователям доступна одна команда с теми же режимами, что в игре:

- `/item алмаз` или `/item diamond` — топ игроков по конкретному ресурсу;
- `/item железный слиток` — русское название из нескольких слов;
- `/item Alex` — все ресурсы игрока;
- `/item Alex алмаз` — количество конкретного ресурса у игрока;
- `/item player Stone` — явный поиск игрока, если ник совпадает с названием предмета.

Старая команда `/topitem` продолжает работать с теми же русскими и английскими запросами. В меню Telegram показывается только короткая команда `/item`.

Списки выводятся по `pageSize` строк. Кнопки «Назад» и «Вперёд» редактируют одно сообщение и не засоряют тему. Нажимать их может только автор запроса. Ответ бота автоматически удаляется через `messageLifetimeSeconds` секунд, по умолчанию через 5 минут. После удаления или перезапуска бота запрос нужно выполнить заново.

Пользователям из `adminUserIds` дополнительно доступны `/items` и `/status`. `/items` также использует интерактивные страницы. `/id` оставлена служебной командой для настройки.

Бот читает уже загруженный локальный каталог плагина и не требует отдельного процесса или отдельного пользователя MariaDB. Токен можно передать переменной окружения `VAULT_TELEGRAM_TOKEN`, логин и пароль прокси — `VAULT_TELEGRAM_PROXY_USERNAME` и `VAULT_TELEGRAM_PROXY_PASSWORD`. Настоящие секреты не добавляйте в Git.

## Установка и обновление

1. Остановите сервер и сохраните резервную копию папки `plugins/VaultTracker`.
2. Удалите старый JAR VaultTracker и поместите в `plugins` только `VaultTracker-0.4.2.jar`.
3. Запустите сервер. Существующие `config.yml`, `server-id` и `cache-*.mv.db` сохраняются.
4. При необходимости измените `telegram.yml` и выполните `/vtrack reload`. После обновления самого JAR всё равно требуется обычный перезапуск сервера.

В папке плагина находится локальная база `cache-<server-id>.mv.db`. Сохраняйте её в резервной копии вместе с миром. Она содержит регистрации, последние остатки и очередь изменений для MariaDB.

## MariaDB

MariaDB включается в `config.yml` и используется как удалённая копия каталога. Плагину нужны права `CREATE`, `INDEX`, `SELECT`, `INSERT`, `UPDATE` и `DELETE` в выделенной базе. Вместо пароля в файле можно задать `VAULT_DB_PASSWORD`.

Создаются таблицы `vt2_vaults` и `vt2_items`. Отключение MariaDB не останавливает локальный учёт. После восстановления подключения накопленные изменения отправляются автоматически. У разных серверов должны быть разные `server-id`.

## Сборка и проверка

Откройте проект с JDK 21 и запустите `./gradlew build` либо `.\\gradlew.bat build` в Windows. Устанавливать нужно итоговый `build/libs/VaultTracker-0.4.2.jar`; файлы `*-plain.jar` и `*-smoke.jar` серверу не нужны.

Автоматические тесты проверяют локальный каталог, MariaDB-проекцию, поддерживаемые хранилища, вложенные контейнеры, команды, русские названия, конфигурацию Telegram и обработку его команд. Реальное подключение к пользовательскому Telegram-прокси и MariaDB тестами не выполняется.
