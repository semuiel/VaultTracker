# VaultTracker 0.10.6

`/list` получает мир и пинг каждого онлайн-игрока заново на его потоке Paper/Folia. Сохранённый при входе или смене мира список больше не используется. При перелистывании данные также обновляются; срок удаления сообщения не продлевается. Значки по умолчанию: 🌍 обычный мир, 🔥 Незер, 🌌 Энд, ❓ другое измерение. Свои значки и customEmojiId по-прежнему задаются в `list.dimensions`.

В существующем разделе `list` файла `telegramchat.yml` можно добавить:

```yaml
list:
  showPing: true
  messageLifetimeSeconds: 300
```

Не создавайте второй раздел `list`: дополните имеющийся. `showPing: false` скрывает пинг (это также значение по умолчанию для старых конфигов). Пример включённого отображения: `🌍 Alex · 42 мс`. Используется [пинг Minecraft Player.getPing](https://jd.papermc.io/paper/1.21.11/org/bukkit/entity/Player.html#getPing()), как показатель соединения в игровом списке.

При желании в существующем разделе `formats` можно задать:

```yaml
  listRow: "{emoji} {name}{ping}"
  listPing: " · {ping} мс"
```

Старый `listRow` без `{ping}` тоже поддерживает переключатель: суффикс добавляется автоматически. В `listRow` маркер `{ping}` означает весь суффикс, в `listPing` — число миллисекунд. При отключении пинга весь суффикс исчезает.

Удаление происходит через 300 секунд реального времени после успешной отправки (либо срок из конфига). Оно больше не ждёт очередь чата. Ошибки Telegram не теряются: попытка повторяется через 30 секунд, причина пишется в журнал с ограничением частоты. Если сообщение уже удалили вручную, повторов нет. Сроки сохраняются в служебном файле `telegramchat-<id бота>-lists.properties`, поэтому переживают `/vtrack reload` и перезапуск сервера. Токена в файле нет. После запуска просроченные сообщения удаляются при восстановлении связи. Самостоятельно файл редактировать не нужно.

Удаление требует доступности Telegram и разрешений API; при отказе журнал укажет причину. Старые сообщения, отправленные до обновления, не имеют сохранённых сроков и автоматически в новую очередь не попадут. Ограничения удаления определяет [Telegram Bot API](https://core.telegram.org/bots/api#deletemessage).

Замените JAR и перезапустите сервер. Последующие изменения настроек применяются через `/vtrack reload`.
