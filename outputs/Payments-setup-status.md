# Подключение оплаты — подготовлено, ожидает авторизации

На VanillaTEST сервис находится внутри `plugins/VaultTracker/donation-service`. Основной сервер не изменялся. Собственный переносимый Python не требует установки в Windows.

Подготовлены адрес лота 77604794, случайный ключ связи с плагином и конфигурация. `enabled` в `donations.yml` остаётся `false`. Лот остаётся неактивным. Сам платёжный процесс ещё не запущен.

Следующий шаг — локально заполнить `golden_key` в закрытом `config.local.json` сервиса. Ключ из активной браузерной сессии не был извлечён. Не добавлять локальные конфиги с ключами в архивы или Git.

После ввода ключа: выполнить `CHECK.cmd` на компьютере сервера. Это только проверка авторизации без сообщений и начислений. Затем можно запустить `START.cmd`, проверить доступ плагина к сервису и согласовать первый контрольный заказ. Для заказа есть безопасная проверка `--check-order`, не выдающая код и не начисляющая баланс.

Проверено 13 автоматических сценариев на переносимом Python: HTTP-авторизация, повторные коды, бонус за любую оценку, возвраты, отрицательный баланс, чужой продавец и своевременная проверка новых заказов. Реальная покупка, текущая разметка карточки FunPay и доставка кода покупателю пока не проверены.

JAR 0.13.0-preview менять повторно не требуется: на этом этапе дорабатывался только отдельный платёжный сервис.
