# VaultTracker 0.9.0

Остановите сервер, замените старый JAR VaultTracker на `VaultTracker-0.9.0.jar` и запустите сервер. Существующие настройки, привязки и базы сохраняются. Перед заменой сохраните резервную копию папки `plugins/VaultTracker` при остановленном сервере. Нужны Java 21 и Paper/Folia 1.21.11.

## Прокси

При запуске Telegram-клиента рядом с `telegram.yml` создаётся `telegram-proxies.txt`. Можно создать его заранее. Одна строка — один SOCKS5-прокси:

```text
proxy-one.example:1080:username:password
proxy-two.example:1080:username:password
```

Без кавычек. Пустые строки и строки с `#` пропускаются. Пароль может содержать `:`. Непустой список заменяет одиночный прокси из `advanced.proxy`; для такого списка отдельное включение `type: socks5` не требуется. Пустой список сохраняет прежние настройки из `telegram.yml`, включая HTTP-прокси или прямое подключение. После редактирования выполните `/vtrack reload`.

При сетевой ошибке следующий запрос идёт через следующий прокси по кругу. Бот продолжает попытки без ограничения `maxAttempts`; задержка ограничивается `initialDelay` и `maxDelay`. Уже отправленный запрос автоматически не повторяется, чтобы не дублировать сообщения и действия. Уведомления охраны остаются в очереди и повторяются через 5 минут. Учёт игровых хранилищ и запись событий выполняются отдельно от Telegram.

Клиент не меняет глобальный Java Authenticator, ProxySelector или системные параметры прокси. После старой версии, которая меняла эти параметры, нужен полный перезапуск сервера. Файл с паролями не публикуйте в Git.

## Меню

- `/menu`: «Поиск», «Личный кабинет». Поиск доступен до привязки персонажа.
- Кабинет: ресурсы, события, настройки игрока, функции администратора и супер администратора по роли.
- В настройках игрока: переключатель уведомлений, «Всегда», «После выхода», «2 дня», применение и сброс тега. Результаты содержат только успешные группы по названию; если успехов нет, бот сообщает, что тег не изменён.
- Функции администратора: уведомления, список игроков, события администраторов.
- Супер администратор: администраторы бота, список игроков, личный срок админских уведомлений.
- В администраторах бота: действующие роли, добавление администратора/супер администратора, переключатели действий обычных администраторов. Нажатие на роль открывает подтверждение удаления. Основного супер администратора из `guard.yml` и собственную супер роль удалить через меню нельзя.
- Список игроков начинается с онлайн; доступны офлайн, поиск по части ника и страницы. Карточка содержит информацию и действия в заданном порядке. Онлайн-действия для отсутствующего игрока возвращают сообщение о его отсутствии; инвентарь/эндер читаются из последнего сохранения playerdata.
- Права на инвентарь и эндер-сундук, два вида телепортации, выдачу и снятие OP переключаются отдельно. Супер администратор сохраняет полный доступ. Уведомления и история администратора доступны независимо от этих переключателей.

Имена и @теги Telegram сохраняются из сообщений и нажатий пользователя. Для ранее добавленного администратора, который ещё не обращался к этой версии бота, сначала отображается Telegram ID; ему достаточно открыть `/menu`. Если @username у пользователя нет, отображается доступное имя.

Изменения ролей и прав сохраняются в `guard-data.mv.db` и действуют сразу, в том числе на старых кнопках. Каталог поиска, суммарный топ в шалкерах и группировка уведомлений за 10 секунд сохранены.

Автоматические проверки используют локальный тестовый SOCKS5-сервер. Подключение через ваши реальные прокси и проверка на рабочем Minecraft-сервере в эту проверку не входят.
