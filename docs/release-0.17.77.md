# VaultTracker 0.17.77: будущая установка

Во время разработки к рабочему Minecraft, SSH, MariaDB, платёжному процессу и reverse proxy подключений не было. Ниже инструкция для выбранного вами окна обновления, не выполненные действия.

## Файлы

- `VaultTracker-0.17.77-preview-folia26.jar` — собранный Java-плагин для текущей ветки Folia 26.
- `payment-service-0.17.77.zip` — согласованный комплект Python-модулей, requirements и документации. В нём нет config.local.json, базы, runtime, .venv, токенов или действующих ключей.
- `SHA256SUMS.txt` — контрольные суммы релизных файлов.
- `report-0.17.77.md`, `voting-eligibility.md`, `bot-analytics.md` — поведение, ограничения и результаты проверок.

## Порядок обновления

1. Сначала запланируйте обновление платёжного сервиса. Остановите только его штатным способом и убедитесь, что процесс завершился. Сделайте резервную копию всей его папки в остановленном состоянии, включая config.local.json и donations.sqlite со вспомогательными файлами. Не копируйте только один активный SQLite-файл как согласованный backup.
2. Разверните содержимое payment-service ZIP в ту же папку, заменив только файлы кода. Обязательно должны попасть `vote_schema.py`, `vote_monthly.py` и `voting.py` вместе с остальными модулями комплекта. Оставьте существующие config.local.json, runtime и базу. Не запускайте configure.py/SETUP ради обновления.
3. Запустите прежний START.cmd. Миграции добавят таблицу eligibility и три приза. Существующие кошельки и закрытые месяцы сохранятся. Сначала обновляется сервис: новый Java UI должен читать уже защищённый backend. Старый Java-клиент с новым сервисом совместим.
4. JAR замените самостоятельно во время штатной остановки выбранного Minecraft-сервера. Не используйте hot reload. Во время разработки ни один JAR в production не заменялся.
5. В существующем telegram-menu.yml при необходимости поменяйте только заголовок `texts.voting.user` на «🗳 Голосования», сохранив `{providers}` и своё оформление. Не заменяйте весь конфиг шаблоном.
6. Новую аналитику включайте только после добавления её HTTPS-маршрута. Подготовленные значения для telegram.yml:

```yaml
botAnalytics:
  enabled: true
  accessChatId: -1002748891862
  publicUrl: "https://flexity.fun/bot-analytics/"
  timezone: "Asia/Novosibirsk"
```

Это предлагаемый адрес нового раздела. Используйте свой действующий HTTPS-домен, если основной Mini App опубликован по другому адресу. accessChatId — ранее указанный административный чат; Root должен быть администратором/создателем именно этого чата. Все прежние настройки telegramAnalytics/coreprotectWeb сохраняются.

7. На существующем HTTPS reverse proxy нужен отдельный маршрут с сохранением пути. Пример для Caddy внутри действующего сайта (это только пример, live Caddy не изменялся):

```caddy
handle /bot-analytics/* {
    reverse_proxy 127.0.0.1:8194
}
```

Не используйте handle_path, который удаляет префикс. Если общий listener CoreProtect настроен на другой порт, укажите его. Нового listener или открытого наружу backend-порта не требуется: используется прежний localhost listener и существующий HTTPS 443. Оставьте bindHost 127.0.0.1. Проверку/применение proxy выполняйте в своём окне обслуживания.

8. После вашего планового запуска откройте Root → Аналитика. Там должны быть CoreProtect, Telegram-статистика и Аналитика бота. Если включение новой аналитики ещё не нужно, оставьте enabled: false: голосования и CoreProtect dropdown от неё не зависят.
9. Root → Экономика → Голосования и награды → Призы ТОП-3: проверьте три суммы и прежний режим ничьей. Первый существующий приз сохраняется; новые 2/3 по умолчанию 200/100. Суточные суммы проверьте в настройках каждой площадки: 2.00 дают суммарно 6.00, но произвольная настроенная награда не перезаписывается.

## После установки

Не выдавайте тестовые деньги реальным игрокам. Проверить отображение таймера можно по следующему настоящему допустимому голосу. Повтор этого provider в течение 24 часов не должен создавать новое начисление или успех-уведомление. Обновите меню кнопкой «Обновить».

CoreProtect dropdown читает co_user/co_username_log через уже настроенного SELECT-only пользователя, без дополнительной учётной записи или порта. Ручные ник и UUID работают при недоступном dropdown. Выбор UUID может отключить автосоставление rollback-команды по прежним правилам безопасности: копируемая команда не должна ошибочно откатывать другого человека с таким же старым ником.

Файлы `bot-analytics.mv.db` и прежние `telegram-analytics.mv.db`/guard data/платёжная база должны входить в согласованный backup. Новую аналитику не переносите без её HMAC key: он внутри того же файла. Произвольная полная история до включения недоступна.

## Откат

Если понадобится откат версии, сначала остановите соответствующий компонент и сохраните новые данные. Верните согласованный backup кода и базы, а не одну старую программу поверх новой схемы. Учтите реальные платежи/голоса после backup: не стирайте их возвратом старой базы без сверки. В рамках этой задачи откат или установка live не выполнялись.
