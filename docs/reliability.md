# Надёжность: версия 0.17.57

## Что изменено

- `SupportRepository` отделяет SQL поддержки от большого `GuardService`, сохраняя одну последовательную очередь БД и совместимость прежних таблиц.
- Нажатие «Отправить» сохраняет обращение и ID исходных материалов до Telegram. Статус `DELIVERY_PENDING` и прогресс переживают перезапуск. Повтор — через минуту; сначала файл и материалы, затем карточка. Неотправленная анкета на разбан уже занимает одну попытку, повторная доставка не расходует новую.
- Неотправленные пользователем черновики форм пока живут в памяти 30 минут. Перезапуск не восстанавливает незавершённую форму.
- Root → Пожертвования → Разблокировать покупки → игрок → подтверждение. Доступный баланс после вычета неподтверждённых средств должен быть неотрицательным. Пополнение само по себе блокировку не снимает. Действие записывается в журнал и идемпотентно по requestId. Ключ сайта разблокировку не разрешает.
- Платёжный сервис хранит доставку каждого уведомления каждому Root в `alert_deliveries`. Ошибка одного получателя откладывает только его доставку на пять минут. Новые уведомления продолжают отправляться. При запросе учитываются только текущие Root ID.
- Один процесс `service.py` обслуживает платежи и голосования. Внешний `POST /voting/minecraft-rating` изолирован своим adapter/service; финансовые JSON API даже при `bind_host: 0.0.0.0` разрешены только с localhost. Голос, его фактическая награда и выдача баланса фиксируются одной SQLite-транзакцией.
- `TelegramWorkQueue`: очередь до 1024 задач, последовательность по Telegram ID, независимые виртуальные workers для разных пользователей. Обновление активного меню после уведомления выполняется в той же пользовательской очереди. Общие карты состояния потокобезопасны.
- Каталог поддерживает готовые суммы и наборы хранилищ по UUID. Общий рейтинг сортируется вне блокировки каталога. Поиск своих ресурсов читает только свои хранилища.
- `LocalStore` помечает пригодные записи `resolved`; миграция старых UUID выполняется при загрузке/повторном разрешении. Обычная отправка ограничивает SQL-выборку, а не только итоговый Java-список.
- `texts` в telegram-menu.yml — стабильные ключи для главного меню и поддержки. Примеры есть в ресурсе. Без ключа прежние `replacements` работают; кастомные эмодзи и контакты сохраняются.

## Установка

Только после резервной копии и согласованного обслуживания. Этот релиз подготовлен локально, production не изменён.

1. Сохранить копии JAR, `guard-data*`, `cache*`, `donations.sqlite*` и конфигов при остановленных соответствующих процессах.
2. Сначала обновить код сервиса (`ledger.py`, `service.py`, `voting.py`, `vote_providers.py`), сохранив config.local.json, ключи и базу. Старый плагин совместим с сервисом; новому плагину нужен новый сервис для voting API.
3. Установить JAR 0.17.57. Новые таблицы/колонки создаются автоматически, старые записи сохраняются.
4. telegram-menu.yml заменять не требуется. При желании добавить только нужные ключи `texts`, сохранив текущие replacements и emojis.

## Границы гарантий

Telegram не предоставляет ключ идемпотентности для отправки сообщения. Если Telegram принял файл/карточку, но ответ потерялся или процесс завершился до записи ID, повтор может создать дубликат этого шага. Уже сохранённые ID не отправляются повторно. Недоступный исходный материал остаётся в очереди; его сбой виден по ID заявки в журнале.

Получение Telegram-обновления по-прежнему отмечается до выполнения действий, чтобы не повторить наказание после аварии. Входная очередь в памяти: аварийно прерванное действие может потребовать повтора пользователем. Обычное закрытие ждёт очередь; при превышении срока пишет о необработанных обновлениях. Сохранённая очередь заявок — отдельная, долговечная.

Прежний JAR не следует ставить поверх работающей новой очереди без плана отката. Исходная контрольная точка Git: `34c9370`; для полного отката сохранять согласованные копии баз и конфигов.

## Продолжение упрощения проекта

`SupportRepository` — первый выделенный модуль хранения. Следующие независимые кандидаты: привязки/роли, личные сообщения, статистика. Переносить по одному, оставляя фасад GuardService и тесты совместимости. Именованные тексты остальных экранов переводить при ближайшей правке конкретного экрана.

Исторические JAR, локальные runtime и вложенная старая копия исключены из обычного поиска через .gitignore; файлы не удалялись и не переносились.
