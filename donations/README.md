# Пожертвования, премиум и голосования

Проверка оплаченного заказа FunPay и доставка кода проверены на тестовом подключении. Новые покупки премиума и админские операции проверены автоматическими тестами; проверка выдачи на живом сервере LuckPerms остаётся отдельным этапом. Основной сервер с игроками не перезапускать ради настройки.

## Схема

Один лот: 1 шт. = 1 монета, базовая цена 1 ₽. Комиссии FunPay/платёжного метода оплачиваются сверх базовой стоимости и не превращаются в монеты. Количество берётся из карточки проверенного заказа, не из сообщения покупателя.

После оплаченного заказа сервис отправляет покупателю 128-битный случайный код. Ввод кода в связанном Telegram-кабинете вызывает повторную проверку заказа на FunPay и атомарное зачисление по UUID персонажа. Root-пользователи получают отдельные уведомления о зачислении, подтверждении заказа, бонусе за отзыв и возврате. До подтверждения заказа зачисление видно в балансе, но недоступно для покупки премиума и списания через сайт; после закрытия заказа оно становится доступным. После фактической оценки закрытого заказа начисляется однократный бонус: 1–5 звёзд дают соответственно 1–5%, с округлением вниз до сотой монеты. Отсутствующая или некорректная оценка бонуса не даёт. Учитывается также оценка без текста по блоку отзыва заказа; актуальную разметку необходимо проверить на контрольном заказе.

Возврат отменяет пополнение и бонус один раз. Сервис проверяет точный заказ в списке возвратов продавца, если метка на странице заказа отсутствует; для уже учтённого заказа он может взять сумму из своей записи, когда FunPay больше не показывает количество. Если монеты уже потрачены, баланс может стать отрицательным, выставляется флаг blocked и создаётся уведомление Root-пользователям. Покупки премиума и списания сайта проверяют blocked и доступный баланс в одной транзакции. Возврат не снимает уже выданные услуги автоматически; Root-пользователь видит уведомление и может снять премиум в меню.

## Премиум и управление балансом

Код пополнения можно отправить в личный чат бота без открытия меню и без срока ожидания ввода. Премиум стоит 600 монет на 30 дней или 1000 на 60 дней; сроки складываются с оставшимся временем. В LuckPerms заранее должна существовать группа `premium`. Выдача идёт через API с абсолютной датой окончания, в том числе офлайн-игрокам. Бессрочный премиум не заменяется платным временным.

Баланс и новая дата премиума сохраняются атомарно. Очередь применения переживает перезапуск; подтверждение выдачи записывается только после успешного сохранения LuckPerms. При сбое после оплаты повторное применение не списывает деньги повторно. В меню показывается ожидание применения. Группа premium удаляется при снятии; другие группы не меняются.

Суперадминистратору доступны выдача на 30/60 дней, собственный срок от 1 до 36 500 дней, бессрочный премиум, снятие, начисление/списание баланса и журнал с Telegram ID исполнителя, игроком, действием, суммой/сроком и датой. Списать больше баланса нельзя. Все списки игроков имеют страницы по 20 строк, поиск, онлайн/офлайн. Журнал — 20 записей на страницу.

Интеграция второго плагина сайта описана в [BALANCE-API.md](BALANCE-API.md): общий баланс, отдельный ограниченный ключ и идемпотентные операции.

## Обновление сервиса

Остановите только сервис, сохраните резервную копию его папки, обновите `service.py`, `ledger.py`, `funpay_provider.py`, `voting.py`, `vote_providers.py` и запустите прежний `START.cmd`. Не заменяйте `config.local.json` и не удаляйте `donations.sqlite`, WAL/SHM. Это по-прежнему один процесс и одно окно. Новые таблицы добавятся автоматически, существующие балансы сохранятся. Для новой версии Java-плагина требуется штатный перезапуск выбранного Minecraft-сервера.

## MinecraftRating

Официальный `promotion.php` принимает `POST application/x-www-form-urlencoded` с полями `username`, `ip`, `timestamp`, `signature`. Подпись равна `SHA1(username + timestamp + SECRET_KEY)`. Успешный ответ — `ok`; ошибка — HTTP 500 с `site_error`. Уникального ID в callback нет, поэтому replay key строится из подписанных nickname и timestamp. Повтор получает `ok`, но не начисляет награду второй раз.

Добавьте в закрытый `config.local.json` секцию `voting` по образцу `config.example.json`. `secret` — Secret Key проекта MinecraftRating, `reward_minor: 500` означает 5.00 монет, `vote_url` показывается игрокам, но secret никогда не возвращается Java-плагину. Root меняет только enabled и reward; изменения сохраняются в SQLite и действуют на будущие голоса.

Endpoint: `POST /voting/minecraft-rating`. MinecraftRating должен видеть полный публичный HTTP/HTTPS URL. При локальном reverse proxy оставьте `bind_host: "127.0.0.1"`; если прокси нет, используйте `bind_host: "0.0.0.0"` и ограничьте firewall только нужным портом. При внешнем bind финансовые маршруты всё равно отвергают не-localhost клиентов. TLS и домен настраиваются вне VaultTracker.

Валидный голос сохраняется как pending, пока Java не сопоставит ник с единственным известным серверу UUID. Затем `vote:<internal-id>` атомарно зачисляет reward в общий donation wallet, а событие получает UUID, отображаемый ник, provider, source/received/credited timestamps и фактическую сумму. История и индексы позволяют позже строить TOP по UUID, provider, периоду и сумме.

Для нового сайта добавьте подкласс `VoteProvider` в `vote_providers.py`, его config и регистрацию в `configured_providers`. Общие таблицы, начисление, статистика и Java UI менять не требуется.

## Отдельный процесс

### Готовая переносимая сборка Windows

В папке сервиса есть собственный Python: системный Python и Java не меняются. `SETUP.cmd` принимает golden_key скрытым вводом и определяет ID продавца. `CHECK.cmd` только проверяет авторизацию и доступ к продажам, ничего не отправляет и не начисляет. `START.cmd` запускает обработку; окно нужно оставить открытым. Запускать эти файлы на самом компьютере Minecraft, не на клиентском ПК через сетевой диск. Вариант конфигурации `seller_id: 0` определяет продавца по авторизованному аккаунту; чужие заказы всё равно отвергаются. Ненулевой ID дополнительно фиксирует ожидаемый аккаунт.

Можно также заполнить только поле `golden_key` в уже подготовленном закрытом `config.local.json`. Остальные значения не менять. Проверка отдельного заказа без отправки сообщений и начислений: `runtime\python.exe service.py --config config.local.json --check-order ORDER_ID`.

Переносимый Python 3.13.15 получен с https://www.python.org/downloads/release/python-31315/ и проверен по опубликованной SHA-256. Зависимости установлены из PyPI; сведения о лицензиях находятся в `runtime/LICENSE.txt` и каталогах `lib/*.dist-info`. Исходники FunPayAPI 1.1.0 доступны на https://pypi.org/project/FunPayAPI/1.1.0/#files .

Сервис запускается на том же компьютере, где работает Minecraft, в отдельной папке вне каталогов миров и других плагинов. Он не обращается к Crafty, RCON, игровым файлам или консоли. По умолчанию HTTP слушает только 127.0.0.1:18763; внешний bind нужен лишь для прямого callback MinecraftRating. Финансовый API требует отдельный случайный ключ и при любом bind принимает запросы только с localhost. Клиент плагина обращается к нему только из Telegram-потоков, с ограниченным временем ожидания.

Зависимость FunPayAPI 1.1.0 — неофициальная библиотека из PyPI. Разметка сайта меняется: неизвестные статусы, количество и чужие заказы отвергаются, деньги по догадке не начисляются. Перед эксплуатацией нужно проверить адаптер на реальной карточке именно вашего заказа. Не передавайте golden_key посторонним: он даёт доступ к аккаунту продавца. Открытый в браузере аккаунт сам по себе не авторизует отдельный процесс.

1. В отдельной папке создать Python 3.11+ venv: `python -m venv .venv`.
2. Установить зависимости в venv: `.venv\Scripts\python -m pip install -r requirements.txt`.
3. Скопировать config.example.json в config.local.json. Файл доступен только владельцу сервиса.
4. Локально заполнить golden_key своего аккаунта; не отправлять его в чат и GitHub. seller_id=0 автоматически определяет продавца, либо задайте его ID явно. Сгенерировать api_key: `python -c "import secrets; print(secrets.token_urlsafe(48))"`. Использовать один и тот же ключ в конфиге сервиса и VaultTracker/donations.yml.
5. Указать точное уникальное название лота в order_marker, category_id=1753 для «Донат Minecraft». Не менять название уже проданного лота в конфиге: старые заказы должны продолжать проверяться. Сначала закончить контрольный заказ; при изменении разметки обновить адаптер.
6. Запуск: `.venv\Scripts\python service.py --config config.local.json`. Запускать на сервере, а не с клиентского ПК через сетевой диск. Настройку автозапуска сделать отдельной задачей без перезапуска основного сервера.
7. В donations.yml плагина указать URL своего лота, api-key и enabled: true. Чтение этого файла выполняется при обращении к меню. Новый JAR устанавливается при согласованной остановке сервера.
8. В меню супер администратора включить кнопку пожертвований. По умолчанию она скрыта.

SQLite хранится рядом с конфигом, файл donations.sqlite; нельзя удалять его, иначе будет потерян журнал защиты от повторной выдачи. Для резервной копии использовать SQLite backup API или остановить только платёжный сервис и скопировать его БД вместе с WAL/SHM. Не копировать конфиги с секретами в публичные архивы. При сбое ответа после зачисления игрок вводит тот же код: повторного зачисления не будет.

Проверки запускаются `python -m unittest discover -s donations -v` из корня проекта. Плагин для Folia 26: `gradlew test shadowJar`; вариант 1.21.11: `gradlew -Plegacy=true test shadowJar` (JDK 21). Файлы разных вариантов нельзя одновременно помещать в plugins.
