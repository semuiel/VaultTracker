# Общий баланс для плагина сайта

API v1: POST JSON на `http://127.0.0.1:18763`. Используется тот же SQLite-журнал, что и Telegram; отдельную копию баланса создавать не нужно.

В закрытом `config.local.json` задайте отдельный случайный `website_api_key` длиной минимум 40 символов, отличный от `api_key`. После изменения перезапустите только платёжный сервис. Пустой ключ отключает интеграцию сайта.

Заголовок: `Authorization: Bearer <website_api_key>`. Ключ хранится только в серверной части второго плагина, никогда в JavaScript сайта, URL или Git. Порт не открывать в интернет. Если сайт работает на другом компьютере, его сервер обращается к вашему плагину через собственный защищённый канал; этот API остаётся локальным.

## Чтение

`POST /wallet`

```json
{"owner":"00000000-0000-0000-0000-000000000001"}
```

Ответ: `balanceMinor` (целое число сотых монеты), `blocked`, `premium`, `premiumUntil` (Unix seconds), `premiumPending`. Премиум здесь отражает покупки/выдачи через сервис; вручную выданные сторонними плагинами группы следует читать из LuckPerms.

## Начисление и покупка на сайте

`POST /donation-change`

```json
{
  "owner":"00000000-0000-0000-0000-000000000001",
  "requestId":"00000000-0000-0000-0000-000000000002",
  "name":"PlayerName",
  "action":"spend",
  "amountMinor":60000
}
```

`spend` списывает; `add` начисляет. 60000 означает 600.00 монет. Сумма от 1 до 100000000 сотых. UUID игрока берётся из проверенной привязки аккаунта на сервере, а не из непроверенного запроса браузера. Начисление разрешать только после проверки соответствующего основания.

Создайте requestId UUID один раз и сохраните его в заказе сайта **до** запроса. При тайм-ауте повторите запрос с тем же requestId и теми же параметрами. Повтор вернёт сохранённый результат без второго списания; другой набор параметров с тем же ID отвергается. Ответ содержит `balanceMinor` на момент операции и `action`; для актуального баланса используйте /wallet.

Недостаток средств и blocked проверяются атомарно внутри списания. Проверка /wallet перед списанием не заменяет эту проверку. Выдачу товара сайт обязан сделать идемпотентной по тому же ID и восстановить после своего перезапуска; баланс API сам товары сайта не выдаёт.

Все операции этого ключа попадают в журнал с источником `website`, переданный actor игнорируется. Доступ к выдаче/снятию премиума, кодам FunPay, очереди и админскому журналу запрещён.

HTTP 200 — операция завершена или ранее выполнена; 400 — запрос/сумма/баланс не подходят; 401 — неверный ключ; 403 — нет доступа к операции; 503 — временная ошибка. На 503 или обрыве связи не создавайте новый requestId.
